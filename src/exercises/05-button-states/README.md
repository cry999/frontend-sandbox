# Lesson 05: 処理中・無効・完了のボタン

進捗: 完了（2026-10-26、レビュー合格）

## 到達点

- 保存前・保存中・完了を管理し、確認状態と合わせて文字・配色・disabledを切り替えた。
- マウス・Enter・Spaceで保存でき、連続操作でも送信は1回。保存中の確認解除でも完了し、完了後は再送信しないことを確認した。
- 幅176px・高さ48pxを維持し、説明文に36pxの高さを確保。360px幅でも保存前・保存中・完了でボタン位置が動かないことを確認した。
- Tabでの輪、無効時のスキップ、390px幅の収まり、ビルド・静的検査を確認済み。
- aria-busyの綴りを修正し、保存中true・完了後falseになることと、常設のstatus領域を確認した。音声による読み上げ自体は未確認。
- 色を文字でも補う理由、状態変更時に幅を保つ理由を確認した。
- 応用「保存しています…」への変更は提案済み・未実施（任意）。

## 目的

保存の状態を文字と見た目で伝える。保存中の二重送信を防ぎ、ラベルが変わってもボタンの幅を保つ。目安30〜60分。

## 編集するファイル

- `ButtonStatesExercise.tsx`: 案内文をボタン・状態管理・状態を伝える文に置き換える。
- `ButtonStatesExercise.css`: 第5回専用のクラスで装飾する。

`npm run dev`で見本と実装を比較する。過去の課題・見本・画面の枠組みは編集不要。第3〜4回の自分の実装を参考にしてよい。

## 用意済みの土台

比較欄はそれぞれ独立している。次の2つをコンポーネントのpropsとして渡している。

- `props.canSave`: 「保存する内容を確認しました」のチェック状態。チェック済みならtrue。
- `props.save()`: 約2秒後に完了するPromiseを返す模擬保存。呼ぶたびに送信回数が1回増える。完了を待つときは`await`を使える。失敗は発生しない。

確認欄、送信回数、「最初から試す」は枠組みが担当する。「最初から試す」で確認欄・回数・自分のコンポーネントの状態が初期状態に戻る。模擬保存自体には二重送信を防ぐ機能を入れていない。

ボタン側の状態は自分で管理する。Reactの`useState`で状態を保持できる。最初に「保存前」「保存中」「完了」のどれを覚えておく必要があるか、紙に書いてから進めてもよい。実際の通信、エラー対応、スピナー、共通部品化は今回の範囲に含めない。

## 観察するところ

- 未確認と保存中は、どちらも押せないが理由は同じか。文字でどう伝えているか。
- 保存中に何度もクリックすると、送信回数はどうなるか。
- 「保存する」から「保存しました」に変わるとき、ボタンや周囲の位置が動くか。
- 色が分からなくても、今の状態を判断できるか。

## 完成条件

| 状態 | ボタンの文字 | 見た目 | 操作 |
| --- | --- | --- | --- |
| 未確認 | 保存する | 薄い灰色の背景・濃い灰色の文字 | 無効、送信しない |
| 確認済み・保存前 | 保存する | 青い背景・白い文字 | 保存できる |
| 保存中 | 保存中… | 青い背景・白い文字 | 無効、追加送信しない |
| 完了 | 保存しました | 緑の背景・白い文字 | 無効、追加送信しない |

- HTMLの`button`に`type="button"`を付ける。押せない状態には`disabled`を使い、見た目だけで無効にしない。
- 保存できるときに操作すると、すぐ保存中になり、模擬保存を1回呼び、完了後に完了状態になる。
- 保存中に確認欄を外しても処理は継続し、保存中の表示から完了へ進む。完了後に確認欄を切り替えても再送信できない。「最初から試す」でやり直す。
- ボタンは全状態で幅176px・高さ48px、角丸8px。文字は16px・太さ600・行の高さ1.5を目安に中央に置く。ラベルが変わっても周囲を動かさない。
- 保存可能なときだけhover・押下色・1px下がる反応を付ける。Tabで選んだときに`focus-visible`の輪を出す。無効時はhover・押下の反応を付けない。
- 色に加えて文字でも状態を伝える。ボタンの近くに説明文を置き、「内容を確認すると保存できます。」「保存できます。」「保存しています。しばらくお待ちください。」「保存が完了しました。」を状態に応じて表示する。
- 説明文を常に存在する`role="status"`の領域に置き、処理中のボタンに`aria-busy`を付ける。説明文の領域にも高さを確保し、改行で周囲が大きく動かないようにする。
- マウス・Enter・Spaceで保存できる。連打しても1回の練習で送信回数は1回。未確認・保存中・完了ではTabでボタンに移動しない。
- 390px程度の幅でも文字や輪が欠けず、横にはみ出さない。

見本の青は通常`#2563eb`、hover`#1d4ed8`、押下`#1e40af`。無効時は背景`#e2e8f0`・文字`#526175`、完了時は背景`#166534`。輪は青色で太さ3px・隙間3px。色の完全一致より状態の伝わり方と動作を重視する。

## ブラウザでの確認

1. 未確認でクリックしても送信されず、Tabでもボタンを飛ばすことを確かめる。
2. 確認欄をチェックし、ボタンのhover・押下・フォーカスを確かめる。
3. 保存を何度も素早くクリックする。保存中の文字がすぐ出て、約2秒後に完了し、送信回数が1回のままかを見る。
4. 「最初から試す」で戻し、Tabで確認欄へ移動してSpaceでチェックする。ボタンにTabで移動し、Enterで保存する。リセット後にSpaceでも試す。
5. 保存中に確認欄を外しても完了するか、完了後に確認欄を切り替えても送信回数が増えないか確認する。
6. ボタンの幅と高さ、周囲の配置を4状態で比べる。390px幅でも確認する。
7. 開発者ツールでdisabled・aria-busy・status領域を確認する。可能ならVoiceOver等で状態変更の読み上げを聞く。
8. 「色だけで状態を伝えない理由」「保存中に幅を保つ理由」を短く説明し、「レビューして」と伝える。

## 準備時の確認

ビルド・静的検査は通過。ブラウザで未確認・保存可能・保存中・完了の表示、全状態の176×48px、Tabでの輪と無効時のスキップ、クリック・Enter・Spaceによる保存、連続操作後も送信回数1回、保存中の確認解除からの完了、完了後の確認変更で再送信されないこと、リセットを確認済み。390px幅でも横にはみ出さないことを確認した。aria-busyとdisabledはDOMで確認し、状態説明はstatus領域に配置。音声による読み上げ自体は未確認。ユーザーの実装のレビューとは区別する。

## レビュー後の応用

保存中のラベルを「保存しています…」に変え、長くなっても幅が安定するように調整する。必要な幅をどう決めたか説明する。
