# アニメーション02：ふわっと浮くボタン

進捗：レビュー合格（2026-10-27）。全30問の第2問。目安30〜60分。

## 到達点

- 外側のbuttonを固定し、内側のspanに面・影・移動をまとめた。外側のhover・focus-visibleから内側を動かし、通常時のtransitionで行き帰りをつないだ。
- ブラウザで通常時の面45px、外側53px、4pxの浮き上がりと影の変化、元の位置への復帰を確認。上下端のクリックで各1回反応し、下端でも押せる範囲の位置・高さは変わらない。
- キーボードフォーカス時の浮き上がりと3pxの輪・3pxの隙間、Enter・Spaceで各1回反応を確認。360px・390px幅で横はみ出しなし。
- 動きを減らす設定ではtransitionとhover・focus-visibleの移動を止め、影と輪を残すCSSを確認。有効時の実動作はブラウザ操作の再現機能がなく未確認。
- ビルド・静的検査は通過。全フレームの時系列計測は未実施。
- ユーザーの観察：「影があることによる目の錯覚」。影の距離・広がりと面の上移動から奥行きを感じると整理した。
- 内側に押下時1px下げる指定が残っている。外側の押せる範囲は固定されており、今回の合格を妨げない。押下の演出は次問で扱う。
- 任意の応用：浮く距離を2pxに変え、4pxとの印象を比べて元に戻す（合格条件外）。
- 次はアニメーション03「押すと沈む」。縮小と影、押した感触を学ぶ。

## 目的

移動と影の変化を連動させ、浮いて見えるボタンを作る。hoverから戻る動きと、動いても押せる範囲が安定することを学ぶ。前回の背景色のtransitionと同じく、通常時と変化後の値をつなぐ。

## 編集するファイル

- `Animation02FloatingExercise.tsx`：案内文を「詳細を見る」というHTMLボタンに置き換える。
- `Animation02FloatingExercise.css`：今回専用のクラスで見た目・状態・動きを作る。

このREADMEと上記2ファイルは同じフォルダにある。見本は`src/reference/`に分離している。画面の枠組み、見本、過去の実装は編集不要。ひな形には解答を入れていない。ライブラリの追加、カウンターや状態管理の実装は不要。

`npm run dev`で表示されるURLを開く。今回の見本と実装欄は上部にあり、過去の課題は下の折りたたみで確認できる。操作回数は各欄で別々に数える。

## まず観察する

1. 見本にポインターを重ねる。文字と青い面の位置、影の下への広がりを別々に観察する。
2. ポインターを離して、通常位置と小さな影へ戻る様子を見る。変化の途中で出入りしても試す。
3. ボタンの下端ぎりぎりにポインターを止める。浮いたあとも、上下に揺れ続けないことを確認する。
4. Tabで選び、輪がすぐ出て、面と影が変わる様子を見る。Enter・Spaceで押せるか試す。

前回は「150msは一瞬」「easeとlinearの違いは感じにくい」という観察だった。今回は時間と速度曲線を300ms・easeに固定し、位置と影が一緒に変わった印象に集中する。

## 完成条件

- `type="button"`のHTMLボタンを1つ作り、「詳細を見る」と表示する。
- 青`#2563eb`の面に白い文字。文字14px・太さ600、面の高さ44px以上、左右の余白24px、角丸8pxを目安にする。
- 通常時は小さな影。hoverとfocus-visibleで面が上へ約4px動き、影が下へ広がり、少し濃くなる。色は変えなくてよい。
- 移動と影だけを約300ms・easeで連動させる。hoverやフォーカスを外すと、同じように滑らかに戻る。輪はアニメーションさせない。
- 周囲の配置や押せる範囲は動かさない。下端にポインターを止めても、浮く・戻るを繰り返さず、その場所でクリックできる。浮いた青い面の上端も押せる範囲に収める。
- Tabで太さ3px・隙間3pxを目安とした青い輪がすぐ見える。Enter・Space・クリックで操作回数が1ずつ増える。
- 360px・390px幅でもボタン・文字・輪が欠けず、横にはみ出さない。hoverが使えなくても操作できる。
- 動きを減らす設定では上下移動とtransitionをなくす。影はすぐ切り替わり、輪とボタン操作は使える。
- 「移動と影がどう変わり、なぜ浮いて見えたか」を一言説明する。正確な影の数値の一致は求めない。

## 段階的に考える

まず通常時の面と影を作り、次に浮いた状態、その後に行き帰りの変化を作る。

今回の移動には`transform`、影には`box-shadow`を使う。影は横方向・縦方向のずれ、ぼかし、色を観察して調整する。transitionの対象をこの2つに絞る。

動いたボタンがポインターから逃げると、hoverが外れて戻り、またhoverになることがある。押せる範囲を担当する部分と、見た目を動かす部分を分ける考え方が役立つ。内部の要素を使ってよい。移動先の面も押せる範囲に収まるよう、外側に余裕を取る。構造やCSSに迷ったら「押せる範囲のヒント」と伝えてください。

前回と同じ`prefers-reduced-motion: reduce`で動きを減らす。今回は時間をなくすだけだと瞬間的な上下移動が残るので、移動そのものも止める。

## 自分の実装の確認

1. 重ねる・離す・途中で出入りする操作を試し、移動と影が一緒に変化するか確認する。
2. 下端でポインターを静止し、揺れ続けないこととクリックできることを確認。浮いた面の上端でもクリックする。
3. ポインターを外した状態でTabを使い、輪を確認。Enter・Spaceでそれぞれ1回ずつ回数が増えるか確認する。Tabで離れると通常状態へ戻ることも見る。
4. ブラウザを360px・390px幅にして、欠けとはみ出しを確認する。
5. OSの「動きを減らす」または開発者ツールの再現機能でreduceを有効にし、移動がなく影だけがすぐ切り替わること、輪と操作が使えることを確認。確認後に設定を戻す。
6. 観察した印象を一言添えて「レビューして」と伝える。
