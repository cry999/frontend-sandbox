# Lesson 01: 基本の塗りつぶしボタン

進捗: 完了（2026-10-26、レビュー済み）

## 到達点

- 見本と同じ幅112px・高さ48pxの塗りつぶしボタンを実装した。
- `type="button"`を指定し、文字を`button`に直接配置した。
- 標準のフォーカス表示を残し、Tabキーで選択位置が見えることを確認した。
- 狭い画面でのはみ出しがなく、型チェック・ビルド・静的検査を通過した。

次は、下記の応用で文字数と余白の関係を確認し、Lesson 02で操作の強弱を学ぶ。

## 目的

「保存する」と書かれたボタンを作り、文字、余白、高さ、角丸、配色の関係を学ぶ。

## 編集するファイル

- `BasicButtonExercise.tsx`: 表示する要素。
- `BasicButtonExercise.css`: ボタンの見た目。

`npm run dev`で表示したページの「見本」を観察し、「あなたの実装」欄に自分のボタンを表示する。見本は実際の保存処理を行わない。この課題でも保存処理は不要。

## 完成条件

- HTMLの`button`要素を使い、「保存する」と表示する。
- フォームを送信しないボタンとして`type="button"`を指定する。
- 専用のクラスを付け、CSSで装飾する。
- 青い背景と白い文字、左右にゆとりのある余白、少し丸い角を見本に近づける。
- 文字が上下左右の中央に見え、欠けたり折り返されたりしない。
- ブラウザの幅を狭めても、ボタンが表示欄からはみ出さない。

ぴったり同じ寸法にすることより、見比べて違いを調整できることを重視する。hover、処理中の状態、アニメーション、共通部品化は後の回で扱う。ブラウザ標準のフォーカス表示は残してよい。

## 確認すること

1. ファイルを保存し、自分のボタンが表示されることを確認する。
2. 文字の大きさ、左右と上下の余白、角丸、色を見比べる。
3. ボタンをクリックして、ページが再読み込みされないことを確認する。
4. 「なぜこの余白・角丸にしたか」を短く説明して、レビューを依頼する。

## レビュー後の応用

「詳しく見る」という文字のボタンに変え、文字数が増えても余白のバランスが保たれるか試す。
