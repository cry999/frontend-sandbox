# Lesson 06: 保存・削除・キャンセルの組み合わせ

進捗: 準備完了・実装待ち

## 目的

3つの操作の優先度を、強弱と配置で伝える。保存は最も見つけやすく、キャンセルは控えめに、削除は危険性が分かり誤って選びにくい位置に置く。全6回の最終課題。目安30〜60分。

## 編集するファイル

- `ActionCombinationsExercise.tsx`: 案内文を3つのボタンと配置用の要素に置き換える。
- `ActionCombinationsExercise.css`: 第6回専用のクラスでボタンと配置を整える。

`npm run dev`で見本と実装を比較する。第1〜5回の自分の実装を参考にしてよい。過去の課題・見本・画面の枠組みは編集不要。

## 用意済みの土台

記事の見出し・説明・削除の注意文、操作結果を表示する常設の`role="status"`領域は用意済み。コンポーネントには以下の関数が渡る。

| props | 呼んだときに表示する結果 |
| --- | --- |
| `props.onSave()` | 保存しました（練習用）。 |
| `props.onCancel()` | 編集をキャンセルしました（練習用）。 |
| `props.onDelete()` | 記事を削除しました（練習用）。 |

見本と実装の操作結果は独立している。各ボタンの操作時に対応する関数を呼ぶ。今回の焦点は優先度と配置なので、保存中の状態管理は不要。実データの保存・削除、画面移動、確認ダイアログ、フォーム、共通部品化は範囲外。

## 観察するところ

- 最初に目に入るボタンはどれか。背景を塗る面積はどう違うか。
- 削除を赤い塗りつぶしにせず、赤い文字にした理由は何か。
- 保存とキャンセルの距離、削除との距離はどう違うか。
- 狭い画面では何をひとまとまりとして折り返しているか。

## 完成条件

| 操作 | ラベル | 見た目 | 役割 |
| --- | --- | --- | --- |
| 保存 | 保存する | 青い背景・白い文字 | 主役。右端に置く |
| キャンセル | キャンセル | 白い背景・灰色の枠線・濃い文字 | 保存のすぐ左に置く |
| 削除 | 記事を削除 | 透明な背景・赤い文字 | 保存・キャンセルと間隔を空ける |

- 3つとも`type="button"`のHTMLボタンにする。それぞれの操作に対応する関数を呼び、正しい結果が表示される。
- 高さは44px以上、文字は14px・太さ600、角丸8pxを目安にする。ボタン同士の文字の高さを揃える。
- 保存・キャンセルは8px程度の間隔で1つのグループにする。削除との間には20px以上の間隔を取る。
- 幅が十分あるときは削除を左側、保存・キャンセルのグループを右側に置く。幅が足りなければ削除の下にグループ全体を折り返し、右に揃える。無理に3つを1行へ詰めない。
- 360px・390pxの画面幅でもラベルが折れたり、ボタンが重なったり、横にはみ出したりしない。フォーカスの輪も欠けない。
- 各ボタンにhover・押下の色変化と、押下で1px下がる反応を付ける。枠線の有無で位置が動かないようにする。
- Tabで選んだときに太さ3px・隙間3pxを目安とした輪を出す。削除 → キャンセル → 保存の順に移動でき、各ボタンをEnter・Spaceでも操作できる。見た目とTabの順番を揃える。
- 削除の意味を色だけに頼らず「記事を削除」という文字でも伝える。既存の注意文と合わせて、元に戻せない操作だと分かるようにする。

見本の保存色は通常`#2563eb`・hover`#1d4ed8`・押下`#1e40af`。キャンセルは枠線`#b6c0cc`・文字`#334155`・hover背景`#f1f5f9`・押下背景`#e2e8f0`。削除は文字`#b91c1c`・hover背景`#fef2f2`・押下背景`#fee2e2`。輪は青色。色や寸法の完全一致より、役割の区別・配置・操作を重視する。

## ブラウザでの確認

1. 見本で3つの操作を試し、どこに目が向くか、ボタン間の距離を観察する。
2. 実装側で各ボタンをクリックし、結果が対応しているか確認する。
3. Tabで削除 → キャンセル → 保存へ移動し、輪を確認する。各ボタンをEnterとSpaceでも試す。
4. hover・押下で文字が読めるか、周囲が動かないかを確認する。
5. 広い画面と360px・390px幅で比較する。狭いときも保存とキャンセルがまとまり、削除とは離れているかを見る。
6. 「保存を最も強く見せた理由」「削除の色と位置を決めた理由」を短く説明し、「レビューして」と伝える。

## 準備時の確認

ビルド・静的検査は通過。ブラウザで見本の3操作をクリック・Enter・Spaceで実行し、対応する結果と実装側への非干渉を確認。Tabの順番と3pxの輪、各ボタンの高さ44px、広い画面の左右配置、360px・390px幅でのグループ単位の折り返し・右揃え・横はみ出しなしを確認した。hover・押下のスタイルはコードで確認し、音声による読み上げ自体は未確認。実装欄は案内文のみ。準備の検証とユーザーの実装レビューは区別する。

## レビュー後の応用

任意で主操作を「下書きを保存」に変え、ラベルが長くなっても優先度とグループのまとまりを保つ。共通化するなら何を共通にし、何を役割ごとに残すか考える。
