# Lesson 03: 操作に反応するボタン

進捗: 準備完了・実装待ち（2026-10-26）

## 目的

「保存する」ボタンを作り、マウスを重ねたとき、押している間、キーボードで選んだときの反応を表現する。押せること・押していること・今どこを選んでいるかが伝わる見た目を学ぶ。

目安は30〜60分。今回は塗りつぶしボタン1つに集中する。

## 編集するファイル

- `InteractiveButtonExercise.tsx`: 案内文を「保存する」ボタンに置き換える。
- `InteractiveButtonExercise.css`: 第3回専用のクラスを付け、通常時と操作時の見た目を書く。

`npm run dev`で開く第3回の「見本」と「あなたの実装」を比較する。第1回の通常時のスタイルを参考にしてよい。第1・2回や`src/reference/`の編集は不要。

操作回数を数える枠は準備済み。クリック処理、実際の保存処理、状態管理、共通部品化、アニメーションは不要。

## 観察するところ

- マウスを重ねたときと、押し続けたときで、背景色がどう変わるか。
- 押したときにボタンは動くか。周りの文字や枠も動いてしまうか。
- Tabキーで見本を選ぶと、輪はどこに出るか。背景と輪の間に隙間があるか。
- Tabで選んだままマウスを重ねたりSpaceを押したりしても、選択位置が分かるか。

## 完成条件

- HTMLの`button`要素を使い、`type="button"`を指定する。
- 通常時は青い背景・白い文字。文字16px・太さ600・行の高さ1.5、上下12px・左右24pxの余白、角丸8pxを目安に、高さ48pxに整える。
- hoverでは背景が少し濃くなり、カーソルからも押せることが分かる。
- 押している間はhoverよりさらに濃くなり、ボタンが1px下に動く。周りの配置やボタンの寸法は変わらない。
- 離すと押下の見た目が戻り、マウスを外すと通常時に戻る。
- Tabで選ぶと、ボタンの外側に太さ3px・隙間3px程度の青い輪が表示される。押下・hover中もキーボードの選択位置が分かる。
- マウスでクリックしたときは独自の輪を出さず、Tabなどキーボード操作では輪を表示する。フォーカス表示を一律に消さない。
- マウスクリック・Enter・Spaceで操作回数が増える。Tabで選ぶだけでは増えず、再読み込みも起きない。
- 390px程度の画面幅でも、ボタンやフォーカスの輪が欠けない。

見本の色は通常`#2563eb`、hover`#1d4ed8`、押下`#1e40af`、輪`#2563eb`。色の完全一致よりも3つの状態の違いと、選択位置の分かりやすさを重視する。

## ブラウザでの確認

1. 通常時の文字・余白・高さを見本と比べる。
2. マウスを重ね、押したままにしてから離し、最後にマウスを外す。各状態が切り替わることを確認する。
3. TabとShift+Tabで見本と自分のボタンを往復し、輪を確認する。
4. キーボードで選んだ状態でEnterを1回押し、操作回数が1回増えることを確かめる。Spaceは押している間の反応と、離したときに1回増えることを確かめる。
5. 輪がある状態でマウスを重ねたりSpaceを押したりしても、選択位置を見失わないか確認する。
6. 画面幅を390px程度に狭めて、ボタンと輪の収まりを確認する。
7. 「hover・押下・フォーカスはそれぞれ何を伝えるか」を短く説明し、「レビューして」と伝える。

## 準備時の確認

ビルド・静的検査は通過。ブラウザで見本の高さ48px、hoverの背景変化、押下中の背景と1pxの移動、マウス操作時に独自の輪が出ないこと、Tabでの輪と移動、Enter・Spaceでの回数加算を確認済み。390px幅でも見本と輪の収まりを確認した。ユーザーの実装はこれから行うため、レビュー合格とは区別する。

## レビュー後の応用

文言を「変更を保存する」に変え、状態が切り替わっても幅・高さや周囲の配置が安定するか試す。
